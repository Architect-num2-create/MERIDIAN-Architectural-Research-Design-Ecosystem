# 16 — MATHEMATICAL / PHYSICAL GRAMMARS

Math should enter MERIDIAN only when the building starts behaving differently because of it.

A number is not interesting because it is precise.

A ratio becomes interesting when changing it changes the room, the light, the structure, the way the body reads the mass.

---

## Start with what is already there

The project already suggests:

- modular aggregation
- radial organization
- stepped vertical transformation
- repeated structural rhythm
- changing distance from a centre
- solid / void relationships

These are enough.

We do not need to invent a mathematical identity for the project before measuring the architecture itself.

---

## Ratios worth watching

Not because they are sacred.

Because they might repeat.

height : width  
void : mass  
centre : peripheral field  
opening : wall  
span : thickness  
distance from centre : size  
lower volume : upper volume

If the same relationship keeps appearing in different parts of the building, it may be one of the project's hidden rules.

That is much more valuable than choosing a famous proportion afterwards.

---

## Radial geometry

Radial organisation deserves a closer look.

Does every element share one centre?

Probably not.

There may be:
- one dominant centre,
- several local centres,
- shifted centres,
- overlapping radii,
- a centre that is spatial rather than geometric.

That difference could become important.

A radial system does not have to mean symmetry.

It can mean **everything is being affected by a centre**.

---

## Physical behaviour

The physical side should stay close to the architecture.

How far can a span go before the section changes?

How thick does a wall need to become?

What happens when a roof rises in steps?

What happens to daylight when the opening moves deeper?

What happens to the perceived scale when the same module grows?

These questions can turn geometry into design knowledge.

---

## The rule

Do not search for a formula first.

Measure first.
Draw first.
Build sections.
Compare variants.

Then see whether mathematics is already hiding inside the architecture.

If it is not, we do not need to force it in.
