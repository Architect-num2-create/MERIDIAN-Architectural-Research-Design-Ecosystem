# Blind Spots, Red Team, Peer Review

### Blind spots
Things the project cannot see about itself because it built them from the inside.

- **BS1.** The numerology (7, 5, 185) reads as intentional to a reader who's told it's intentional, and reads as coincidence inflated into myth to one who isn't. The project has no built-in way to signal which reader it's talking to, and currently assumes the sympathetic one by default.
- **BS2.** The hidden mysterious name / private identity layer is invisible almost by definition — the project cannot audit whether it's actually hidden well, because the only person who could judge that already knows exactly where it is.
- **BS3.** The Aperture Core is described in language flexible enough to satisfy both a historian and an engineer — which is also, structurally, the exact shape of language that satisfies neither, if either one presses hard. No one in either camp has been asked to press hard yet.
- **BS4.** Every review this project has had so far — an AI model's structural critique of the repo, this dossier itself — has come from a sympathetic collaborator. None has come from a hostile stranger with nothing invested in the project succeeding.

### Red team
Entries written as if the project's harshest fair critic got to speak. No rebuttal attached — that's the point.

- **RT1** (on symbolic vs. structural, see C1): "You're using the word 'plausible' to do the work of 'proven,' and hoping the reader is too charmed by the language of transformation to notice the substitution."
- **RT2** (on the unfinished 20/20): "An unfinished sheet getting full marks says more about what the assignment was actually testing than about what you built. You may be building four more dossiers to justify a grade that was never really about finish."
- **RT3** (on openness vs. protection, see C3): "You can't have Silicon Valley's culture of forking and a medieval guild's anxiety about authorship at the same time. Decide which fear is bigger before you pick a license."

### Peer review
Unlike red team, this is the standard of a generous, competent reader — the kind the project's own paper trail is meant to create, since Document 3's references/path is believed to function partly as an archive of the work in its own right. What such a reader flags first: the Discussion section needs to name C1 through C5 directly, rather than let the paper's confident register quietly resolve them by omission. A generous reviewer forgives ambition. They do not forgive a paper that hopes no one asks the question it already knows about.
